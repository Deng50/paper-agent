## 主要功能与需求口径

这是单用户文献情报助手。FastAPI 提供鉴权 API，Streamlit 展示每日推送、历史对话和偏好画像。APScheduler 每日触发 LangGraph agent，通过 arXiv、Semantic Scholar、Crossref、OpenAlex 四源拉取元数据，完成跨源去重、Haiku 批量评分、Markdown 保存和邮件推送。用户可追问历史论文、重跑检索、提交反馈。反馈定时派生为日志，画像更新任务据此调整次日检索偏好。PostgreSQL 保存用户、推送审计、反馈和 LangGraph checkpoint；论文、画像、会话的可读记忆保存在文件系统。

依据 `CLAUDE.md`、README、`docs/01_PRD.md` 至 `05_roadmap.md`、API/数据模型文档及最近交接记录核对实现。文档存在历史口径差异：当前 chat 不开放 `profile_update` / `write_file`，画像由定时任务更新；这是最新交接明确的产品选择，未按旧 PRD 恢复聊天写画像。当前只接入四源元数据，不启用上游 MCP 服务或 PDF 全文功能。

## 尚待开发或需要外部验证的部分

### 主项目路线图与运行边界

- A/B 画像评估、带真实期望会话 ID 的中文召回黄金集、连续 7 天反馈效果，需要真实数据与模型调用；当前 `eval_cn_recall.py` 并不等同于完整画像 A/B 脚本。
- 定时备份/恢复演练、连续失败告警、每源状态审计可视化、`rebuild_session_md --all` 尚未完整实现。数据库 `source_status` 字段不是已完成的每源健康看板。
- 推送进程被硬杀后的 `running` 状态没有自动过期领取策略；当前需要运维确认后恢复。定时调度本身不能保证断电或重启期间自动补跑。
- 单用户反馈的短时间重复检查没有数据库唯一窗口约束；当前顺序请求路径已实现，极端并发重复提交尚无 PostgreSQL 并发验收。
- 多次独立搜索的跨调用统一源限流、网络长期抖动和大型 memory 目录性能仍需真实负载验证。
- session `topics` 自动提取、PDF 全文/RAG、更多数据源、SQLite FTS 等属于历史交接的后续功能，不把旧占位字段或未来计划标成已完成。

### 未启用的上游 Vendor 扩展

以下不是本项目四源运行链路，也没有在本次审查中启用；不得把主套测试通过解释为它们可上线：

- **ACM/IEEE**：即使配置 API key，search/download/read 仍显式 `NotImplementedError`，属于未完成连接器。
- **OpenAIRE、DBLP、PubMed、Google Scholar、Unpaywall 等**：部分直接 PDF 下载或全文读取不支持；元数据源不必具备原文托管能力。PDF/MCP 依赖按本项目约束未安装。
- **bioRxiv/medRxiv**：查询按分类解释，分页逻辑只处理首批；不能当作已经满足通用全文检索或完整分页的来源。
- **CiteSeerX/OpenAIRE/Sci-Hub**：继承上游的 TLS 校验降级/关闭及外部下载 URL 行为仍需专项硬化；没有在本次运行中调用。独立 MCP server 的下载路径/URL 输入也不受主项目 memory 白名单保护。
- **PMC 等其他 PDF 分支**：仍存在上游 XML 叶节点判断、下载响应验证、超时、稳定 ID 或多条件过滤等需进一步整理的边界。它们未进入本项目检索可用源集合。
- 上游测试含导入/装饰器阶段联网、真实下载、宽松 `len >= 0` 断言和吞异常的测试，因此没有整套直接联网执行；这类测试不能作为可靠的离线验收结果。

上述后续事项具有明确边界。本次修复提高了现有主流程的正确性并补齐两项已经承诺的记忆/画像界面能力，不宣称全仓库或外部依赖不存在其他缺陷。
